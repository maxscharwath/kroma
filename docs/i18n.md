# Messages

Every user-visible string is a key. The engine is `@kroma/i18n` (TypeScript) and
`kroma-i18n` (Rust): the same flat `{ "key": "template" }` catalogs, the same
`{name}` interpolation, `$t(other.key)` quoting and CLDR plurals, so a
notification the server renders reads like the screen that shows it.

## One folder per language, one file per namespace

The core catalogs live in `packages/core/src/locales/<locale>/<namespace>.json`.
A namespace is the first segment of a key: `player.play` lives in
`en/player.json` and `fr/player.json`, and nothing else may live there. Keys stay
fully qualified inside the file, so a grep for `player.play` still lands on the
line that defines it.

`packages/core/src/locales/catalogs.ts` is the index. It imports every namespace
that ships up front and lists the ones fetched on first use:

```ts
export const catalogs = { en: { ...aboutEn, ...accountEn /* ... */ }, fr: { /* ... */ } };

export const lazy = {
  admin: () => part(import('./en/admin.json'), import('./fr/admin.json')),
};
```

The types come from these imports, so `MessageKey` covers every namespace, lazy
ones included, and `t('admin.title')` autocompletes and typechecks the way it
always did. The index is hand-written because Metro cannot glob; a test in
`catalogs.test.ts` fails with the file's name when it disagrees with the disk.

The server needs no list: `server/crates/kroma-engine/build.rs` walks the same
folders and embeds every file, and the builder merges a locale's parts (a key two
parts both define is a build error).

### Adding a namespace

1. Create `locales/en/<namespace>.json` and `locales/fr/<namespace>.json`, keys
   prefixed `<namespace>.`, sorted.
2. Import both in `catalogs.ts` and spread them into `catalogs`, or add a loader
   to `lazy` instead.
3. `bun run test packages/core/src/locales` tells you what you forgot.

Adding a key to an existing namespace is editing two JSON files. A
`$t(...)` reference may quote any eager key; an eager message may not quote a
lazy one.

## Lazy namespaces

A namespace only one surface reads is a cost to every other: the admin console
alone was a third of the catalog bytes the televisions downloaded. A namespace
listed in `lazy` is not in the entry bundle. Its keys behave like any other:

- **A route that knows it needs the namespace loads it first.**
  `loader: () => loadNamespaces('admin')` on the TanStack route, so the page
  never paints a key. The admin layout route does this for `admin`, `jobs` and
  `logs`.
- **A miss loads it anyway.** The first `t('admin.x')` whose namespace has not
  landed starts the fetch, renders the key meanwhile, and the provider redraws
  when the catalog arrives. Forgetting a loader costs a flash, never a broken
  screen. A fetch that failed is not retried from a miss, only from an explicit
  `loadNamespaces`.

`loadNamespaces` is idempotent and shares a fetch across concurrent callers. On
a Vite shell each lazy namespace is its own chunk; on Metro the dynamic import
resolves from the one bundle, so a native shell loses nothing and gains nothing.

Choose lazy for a namespace that is large and read by one surface. Everything
the first screen of any shell can show stays eager.

## Modules

A module ships `locales/{en,fr}.json` beside its `module.json`; its front end
registers them as a scope, layered ahead of the core catalogs for that module's
pages only. Nothing here changes for modules: a module's catalog is already one
namespace, named by its id.

## Dev tools

The in-app panel (`@kroma/i18n-devtools`, dev server only) marks every string
with the catalog that answered: `[core/player.play]`, `[tv.kroma.torrents/x]`,
`[missing/foo]`, and `[core@en/foo]` where the fallback locale spoke. A lazy key
shows as `missing` until its namespace lands.
